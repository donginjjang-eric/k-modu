# K-MODU 뷰티 사업자 가입·운영 PRD

상태: 제안 초안. 작성일: 2026-11-11.

## 1. 목적

한국 뷰티 브랜드 담당자가 스스로 가입하고 브랜드를 등록한 뒤, K-MODU 운영팀의 확인을 거쳐 상품과 크리에이터 협업을 관리하게 한다. 운영팀은 신청자, 브랜드, 공개 상품, 캠페인을 한 흐름에서 추적한다.

핵심은 **가입 계정**, **확인된 사업자/브랜드**, **공개 가능한 상품**을 서로 다른 상태로 다루는 것이다. 구글 로그인이 끝났다는 이유만으로 사업자 또는 상품이 검증된 것으로 표시하지 않는다.

## 2. 현재 제품과 해결할 문제

| 항목 | 현재 확인된 구현 | 이번 PRD의 방향 |
|---|---|---|
| 가입 | `/apply`에서 구글 로그인 후 브랜드 분야와 담당자 정보를 입력한다. | 뷰티 사업자용 문구·증빙·상태 안내를 추가한다. |
| 승인 | 신청 API가 브랜드를 `approved`, 작업공간을 `active`로 즉시 만든다. | 확인 전에는 `pending`으로 저장하고 운영자 검토를 거친다. |
| 사업자 정보 | 브랜드명, 담당자, 연락처, 소개가 중심이며 사업자 식별·증빙 데이터가 없다. | 사업자 식별 정보와 확인 상태를 별도로 저장한다. |
| 센터 | 브랜드, 상품, 캠페인, 제안, 콘텐츠, 주문/성과, 정산 화면이 있다. | 기능을 재사용하되 상태에 따라 편집·공개·모집 권한을 구분한다. |
| 관리자 | 브랜드/회원/상품 목록과 승인 동작이 있다. | 뷰티 신청 검토 큐와 반려 이유, 이력, 기존 상품 연결을 보강한다. |
| 상품 공개 | 신규 상품 승인 기본값이 `approved`이고 공개 상태는 별도다. | 브랜드 승인과 상품 공개 검수를 독립시킨다. |

현재 코드 확인만으로 운영 DB의 실제 브랜드·상품 소유 관계까지 단정하지 않는다. 출시 전에 데이터 실사를 해야 한다.

## 3. 대상과 대표 흐름

**사업자 담당자.** 뷰티 페이지에서 `브랜드 입점·상품 등록`을 선택한다. 구글 로그인 → 브랜드/사업자 기본 정보 입력 → 신청 접수 → 상태 확인 → 승인 후 센터 진입 → 브랜드 프로필 및 상품 등록 → 상품 공개 요청 → 크리에이터 협업 운영 순서로 진행한다.

**K-MODU 운영자.** 새 신청을 확인한다. 중복 브랜드와 사업자 정보, 담당자 연락처, 상품 판매·협업 가능성을 검토한다. 승인·보완 요청·반려를 기록한다. 승인 후 상품과 캠페인 운영 상태를 모니터링한다.

**기존에 사이트에 올라온 브랜드.** 새 가입자가 기존 브랜드를 선택해 소유권 연결을 요청한다. 운영자가 기존 담당자 및 자료를 확인하기 전까지 자동 연결하지 않는다. 기존 상품의 공개 상태와 이미지 주소는 연결 과정에서 변경하지 않는다.

## 4. 제안하는 운영 정책

1. **계정은 즉시 생성.** 로그인 자체는 허용한다. 신청 전에도 뷰티 페이지는 볼 수 있다.
2. **브랜드 신청은 검토 대기.** 신청서를 제출하면 접수 번호, 접수일, 검토 상태를 보여준다. 제출 직후 공개 브랜드나 상품을 만들 수 없다.
3. **사업자 확인은 운영자가 수행.** 사업자 등록 식별 정보, 상호, 담당자, 연락처, 홈페이지 또는 공식 판매 채널을 받는다. 증빙 파일은 필요할 때만 요청하며 비공개 저장과 접근 제한을 적용한다. 구체적인 필수 항목은 운영 정책 확정 후 고정한다.
4. **승인 후 센터 활성화.** 브랜드 프로필·상품 초안 편집을 허용한다. 승인 결과와 보완 요청 사유는 신청자가 로그인 화면에서 확인한다.
5. **상품 공개는 별도 결정.** 상품 초안은 저장 가능하지만 공개 목록과 캠페인에는 품질 검토를 통과한 상품만 사용한다. 사진 권리, 상품명, 카테고리, 국가별 판매 정보, 협업 가능 여부를 확인한다.
6. **기존 데이터 보호.** 기존 승인 브랜드와 공개 상품을 일괄 대기 상태로 되돌리지 않는다. 신규 신청부터 새 규칙을 적용하고 기존 브랜드는 단계적으로 확인한다.

## 5. MVP 범위

### 5.1 가입과 신청

- `/beauty`의 주요 행동 버튼을 `브랜드 입점 신청`으로 명확히 연결한다. 기존 `제품 입점 문의`는 상담 경로로 남길지 신청 경로로 합칠지 결정한다.
- `/apply`에 뷰티 전용 진입 맥락을 전달하고 패션 중심 문구인 `디자이너 실명`, `룩북`, `스타일`을 뷰티 맥락에 맞게 바꾼다. 패션 신청 화면의 기능은 유지한다.
- 이메일/전화, 브랜드명, 사업자 식별 정보, 공식 채널, 브랜드 소개, 주요 품목, 희망 진출국을 받는다. 입력 중 임시 저장과 재접속 복원을 제공한다.
- 같은 사용자가 이미 신청 중인 같은 브랜드를 중복 제출하지 못하도록 한다. 크리에이터 계정 보유자는 뷰티 사업자 작업공간을 별도로 신청할 수 있다.
- 개인정보와 증빙 파일의 보관·삭제 정책은 출시 전 운영자와 확정한다.

### 5.2 상태와 권한

- 신청 상태: `작성 중 → 접수 → 확인 중 → 보완 요청 → 승인` 또는 `반려`.
- 브랜드 작업공간 상태: `pending / active / disabled / rejected`. 화면 표시는 신청 상태와 일치해야 한다.
- `pending`은 접수 상태 화면만, `active`는 본인 브랜드 센터만 열어준다. `disabled`는 수정·공개·모집을 중단한다.
- 서버의 모든 상품·캠페인 API에서 로그인 사용자, 선택 작업공간, 브랜드 소유권을 확인한다.
- 복합 브랜드 계정과 여러 브랜드를 운영하는 계정은 기존 작업공간 전환 구조를 활용한다.

### 5.3 관리자 운영

- 신청 목록에 `뷰티 / 패션`, 접수일, 담당자, 상태, 검토 담당자, 마지막 처리일 필터를 제공한다.
- 상세 화면에 신청 정보, 제출 자료, 중복 후보, 기존 사이트 상품·브랜드 연결 후보, 처리 이력을 보여준다.
- 승인, 보완 요청, 반려, 비활성화 시 담당자와 이유를 남긴다. 실수로 처리했을 때 재검토할 수 있게 한다.
- 관리자 등록 브랜드와 사업자 본인 신청 브랜드를 구분해 표시한다.
- 기존 상품 연결은 운영자 승인 작업으로 처리하고, 연결 전후 상품 소유권·공개 상태를 기록한다.

### 5.4 사업자 센터 첫 사용

- 승인 후 첫 화면에 `브랜드 프로필 → 상품 초안 → 공개 요청 → 캠페인`의 진행 상태를 표시한다.
- 상품 등록 시 사진, 상품명, 카테고리, 핵심 특성, 소비자가/공급가, 판매 국가, 제공 가능한 샘플, 공식 상세 URL을 입력한다. 가격과 국가별 판매 가능성은 공개 표시 여부를 별도로 선택한다.
- 운영자가 상품을 반려하거나 보완 요청하면 수정할 항목을 상품 화면에서 확인한다.
- 이미 있는 캠페인·제안·주문·정산 화면을 재사용한다. 샘플 배송 주소나 실제 거래·결제 자동화는 MVP에 포함하지 않는다.

## 6. 화면 구성

| 화면 | 사업자에게 보여줄 핵심 정보 | 운영자에게 보여줄 핵심 정보 |
|---|---|---|
| 뷰티 공개 페이지 | 브랜드 입점 버튼, 절차, 예상 제출 자료 | 해당 없음 |
| 신청서 | 3단계 입력, 임시 저장, 제출 전 요약 | 해당 없음 |
| 신청 상태 | 접수일, 현재 단계, 보완 요청 내용, 재제출 | 해당 없음 |
| 뷰티 센터 홈 | 프로필·상품·캠페인 준비 상태와 다음 행동 | 해당 없음 |
| 브랜드 신청 관리 | 해당 없음 | 신규/보완/승인/반려 큐와 중복 후보 |
| 상품 검수 | 해당 없음 | 공개 요청 상품, 이미지, 정보, 반려 이유 |

모바일 신청서는 한 화면에 한 단계씩 보여주고, 자료 업로드 실패 시 입력 내용을 잃지 않도록 한다.

## 7. 데이터·상태 설계 원칙

- 기존 `users`, `designers`, `user_workspace_memberships`, `products` 구조를 사용한다. 사업자 확인 정보와 검토 이력은 공개 브랜드 프로필과 분리한다.
- 사업자 식별 정보에는 조회 권한을 제한하고 관리자 목록에는 일부만 표시한다. 원본 증빙 파일을 공개 이미지 저장소에 두지 않는다.
- 신청·승인·보완·반려·상품 공개의 전환을 시간, 처리자, 이유와 함께 기록한다.
- 신청 상태와 브랜드 승인 상태, 상품 공개 상태를 하나의 플래그로 합치지 않는다.
- 운영자가 기존 상품을 계정에 연결할 때는 브랜드 ID와 상품 소유 관계를 검증하고, 변경 전 상태를 남긴다.

## 8. 이번에 만들지 않는 기능

- 결제, 계약 전자서명, 세금계산서 발행, 자동 정산.
- 외부 쇼핑몰 주문·재고 연동과 매출 자동 추적.
- AI가 사업자 또는 상품의 진위를 자동 승인하는 기능.
- 신규 사업자가 기존 공개 브랜드를 클릭 한 번으로 가져가는 기능.

후속 단계에서는 팀원 초대, 샘플 발송 추적, 국가별 규정 체크리스트, 협업 제안 템플릿, 성과 리포트를 검토한다.

## 9. 출시 순서

1. **현재 흐름 정합성.** 신청 직후 자동 활성화를 대기 상태로 바꾸고, 신청/로그인/관리자 문구를 실제 상태와 맞춘다. 기존 데이터는 유지한다.
2. **사업자 확인과 관리자 큐.** 뷰티 신청 필드, 비공개 자료, 중복 확인, 승인·보완·반려 이력, 상태 화면을 만든다.
3. **상품 공개 관리.** 승인된 사업자만 상품 초안을 저장하고, 운영자가 공개를 결정한다. 기존 공개 상품은 별도 실사 후 소유권을 연결한다.
4. **협업 운영 개선.** 캠페인 신청부터 콘텐츠, 성과, 정산의 수동 운영 데이터를 일관되게 연결한다.

## 10. 수용 기준

- 미로그인 사용자는 신청 전 로그인으로 안내되고, 로그인 후 작성 중인 신청서로 돌아온다.
- 신규 뷰티 신청 직후 브랜드와 상품은 공개 목록에 나타나지 않으며, 신청자는 접수 상태를 확인한다.
- 운영자 승인 시 해당 계정에만 뷰티 센터가 열리고, 패션/크리에이터 데이터와 섞이지 않는다.
- 운영자 보완 요청과 반려 이유가 신청자에게 보인다. 재제출 시 이전 입력을 복원한다.
- 승인 사업자가 자기 상품을 수정해도 다른 브랜드 상품에 접근할 수 없다.
- 상품 공개 전에는 뷰티 목록과 캠페인 선택에 나타나지 않는다. 검수 완료 후 해당 브랜드의 상품만 나타난다.
- 기존 뷰티 상품의 이미지·공개 상태는 이관 전후 동일하다.
- 관리자 목록에서 신청 → 승인/반려 → 상품 공개까지 처리자와 시각을 추적할 수 있다.
- PC와 모바일에서 가입, 보완, 승인 후 첫 상품 등록 흐름을 실제 계정으로 검증한다.

## 11. 성과 지표

초기 4주 동안 신청 시작 대비 제출 완료율, 접수부터 첫 검토까지 걸린 시간, 보완 재제출률, 승인 후 7일 내 첫 상품 등록률, 첫 상품 공개까지 걸린 시간을 본다. 목표치는 실제 기준선 수집 후 정한다. 자동 매출·정산 수치는 검증 가능한 데이터가 생기기 전까지 성과 지표로 사용하지 않는다.

## 12. 결정이 필요한 정책

1. 사업자 확인 전 `프로필/상품 초안` 편집을 허용할지. 이 PRD는 승인 후 편집을 기본안으로 둔다.
2. 사업자 번호 및 증빙을 신청 시 필수로 받을지, 보완 요청 단계에서 받을지. 이 PRD는 식별 정보를 신청 시 받고 파일은 필요할 때 요청하는 안이다.
3. 상품 공개를 운영팀 전수 검수로 시작할지. 이 PRD는 초기에는 전수 검수, 운영량이 늘면 위험 기반 검수로 전환하는 안이다.
4. 기존 수동 등록 브랜드의 소유권 연결을 언제 시작할지. 이 PRD는 신규 가입 체계 안정화 후 개별 연결하는 안이다.
