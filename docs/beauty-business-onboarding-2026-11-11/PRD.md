# K-MODU 뷰티 브랜드 간편 가입·상품 셀프 등록 PRD

상태: 사용자 방향 반영 초안. 갱신일: 2026-11-11.

## 1. 제품 결정

뷰티 브랜드 담당자는 구글 로그인과 최소한의 브랜드 정보만으로 가입한다. 사업자등록증 제출과 운영자 사전 승인은 요구하지 않는다. 가입 직후 뷰티 브랜드 센터에 들어가 상품을 등록하고 공개할 수 있다. 문제가 생기면 운영자가 상품을 즉시 내리거나 브랜드 이용을 중단한다.

**가입 화면은 뷰티 전용으로 분리하고, 회원 시스템은 공유한다.** 뷰티 페이지의 버튼은 뷰티 전용 짧은 가입 화면으로 연결한다. 기존 패션 디자이너 가입 화면은 유지한다. 두 화면은 같은 구글 로그인, 사용자 계정, 브랜드/작업공간 데이터 모델을 사용한다. 이미 있는 `/dashboard/beauty`를 뷰티 브랜드 센터로 계속 사용한다. 별도 데이터베이스나 두 번째 로그인 시스템은 만들지 않는다.

## 2. 왜 필요한가

현재 뷰티 페이지의 `제품 입점 문의`는 이메일 문의로 이어진다. 공통 `/apply` 화면에는 패션 중심 표현인 `디자이너 실명`, `룩북`, `크리에이터 무드`가 포함되어 있다. 반면 신청 서버는 이미 브랜드와 작업공간을 즉시 활성화하고, 신규 상품도 기본적으로 자동 승인한다. 따라서 뷰티 브랜드에 필요한 일은 승인 절차를 추가하는 것이 아니라 **입구를 쉽게 만들고, 운영자가 문제가 있는 등록을 확실하게 처리하는 것**이다.

기존 기능을 재사용한다.

| 이미 있는 것 | 이번에 보강할 것 |
|---|---|
| 구글 로그인, 브랜드별 작업공간, 뷰티 센터 | 뷰티 전용 가입 화면과 첫 상품 등록 안내 |
| 상품 사진 업로드, 상품 등록·수정, 공개 카탈로그 | 최소 입력, 공개 전 미리보기, 저장/공개 상태 안내 |
| 관리자 브랜드·상품 목록과 숨김/비활성 동작 | 신고·문제 처리 대기열, 이유·이력, 복구, 재등록 차단 |

운영 DB의 실제 브랜드 수와 기존 상품 소유 관계는 별도 실사 전까지 추정하지 않는다.

## 3. 사용자 흐름

1. 방문자가 `/beauty`에서 **뷰티 브랜드 시작하기**를 누른다.
2. 구글로 로그인한다. 로그인 뒤 작성 중이던 뷰티 가입 화면으로 돌아온다.
3. 브랜드명, 담당자명, 연락 이메일, 상품 분야만 입력한다. 홈페이지·인스타그램·한 줄 소개는 선택이다. 사업자등록증, 사업자번호, 주소는 이 단계에서 받지 않는다.
4. 가입을 완료하면 바로 뷰티 센터가 열리고 **첫 상품 등록** 버튼이 보인다.
5. 대표 사진, 상품명, 분야를 입력하면 상품을 저장할 수 있다. 설명과 추가 사진 등은 나중에 보완할 수 있다.
6. 브랜드가 **공개하기**를 누르면 상품이 뷰티 목록에 나타난다. 임시 저장도 선택할 수 있다. 운영자 사전 승인은 없다.
7. 브랜드는 자기 상품을 수정·숨길 수 있다. 운영자가 문제를 발견하면 상품만 내리거나 브랜드 전체를 중단한다.

기존에 K-MODU에 수동 등록된 상품이 있는 브랜드는 새 계정에서 자동으로 가져오지 않는다. 운영자가 기존 브랜드와 계정의 연결을 확인한 뒤 소유권을 넘긴다.

## 4. 가입 화면 분리 범위

추천 경로는 `/beauty/join`이다. 경로명은 구현 시 기존 정적 페이지 라우팅과 충돌하지 않는지 확인한다.

- `/beauty`의 이메일 문의 버튼 옆에 **뷰티 브랜드 시작하기**를 주요 버튼으로 둔다. 이메일 문의는 상담이 필요한 경우를 위해 유지한다.
- 뷰티 전용 화면은 제품 등록을 목적으로 설명한다. `디자이너 실명` 대신 `담당자명`을 쓴다.
- 패션 `/apply`를 복사해 별도 시스템으로 키우지 않는다. 공통 로그인·브랜드 생성 로직은 재사용하되, 뷰티 입력 항목과 문구를 분리한다.
- 한 사용자가 패션과 뷰티를 모두 운영하는 경우 기존 작업공간 전환 메뉴를 사용한다. 같은 브랜드를 잘못 중복 생성하지 않도록 가입 화면에서 기존 보유 브랜드를 보여준다.

## 5. 가입·상품 등록 정책

### 가입

- 구글 로그인 계정은 즉시 사용 가능하다. 뷰티 작업공간은 해당 로그인 사용자와 생성한 브랜드에만 연결한다.
- 동일 계정의 같은 브랜드명 반복 제출을 막는다. 다른 사용자가 같은 브랜드명을 등록하려 하면 자동으로 소유권을 인정하지 않고 운영 확인 대상에 표시한다.
- 자동 가입은 `자체 등록`으로 표시한다. 이는 `K-MODU가 사업자를 검증함`을 의미하지 않는다. 공개 화면에 검증 배지를 자동으로 붙이지 않는다.
- 필수 약관 동의와 이미지·상품 정보 게시 권한 확인은 짧게 제공한다. 구체적인 문구와 보관 정책은 출시 전에 확정한다.

### 상품

- 대표 이미지, 상품명, 뷰티 분야는 필수다. 지원 파일 형식·용량 제한은 기존 업로드 규칙을 따른다.
- 최초 저장 상태는 `임시 저장` 또는 `공개` 중 사용자가 고른다. 공개는 승인 대기 없이 반영된다.
- 공개 전 상품 카드와 상세 화면 미리보기를 제공한다. 허위 효능·타인 이미지·연락처 노출 등 위험한 내용을 등록하지 않도록 짧은 안내를 둔다.
- 상품 공개 여부와 관리자 제재 여부는 별도로 저장한다. 관리자가 제재한 상품은 소유자가 `공개`로 다시 바꿔도 노출되지 않는다.
- 뷰티 카탈로그는 공개 상태이며 관리자 제재가 없고 활성 브랜드에 속한 상품만 보여준다.

## 6. 운영자 문제 처리

운영자는 기존 관리자 `브랜드 파트너 관리`와 `상품 관리`에서 다음을 할 수 있어야 한다.

| 상황 | 운영자 행동 | 즉시 결과 |
|---|---|---|
| 이미지·설명이 부적절한 상품 | 상품 내리기, 이유 입력 | 공개 목록·상세·캠페인 선택에서 즉시 제외 |
| 수정 후 재공개 가능한 상품 | 수정 요청, 이유 입력 | 소유자에게 사유 표시, 수정 뒤 운영자가 복구 |
| 사칭·반복 위반 브랜드 | 브랜드 이용 중단, 이유 입력 | 모든 해당 상품이 비공개되고 상품·캠페인 쓰기 차단 |
| 실수로 내린 상품·브랜드 | 복구 | 이전 소유권 유지, 공개 여부는 운영자가 확인해 복원 |
| 방문자·크리에이터 신고 | 신고 내용 확인, 처리 상태 기록 | 미처리 건이 관리자 목록에 남음 |

관리자 조치에는 처리자, 시각, 대상, 이유, 이전/이후 상태를 남긴다. 문제 상품은 삭제하지 않고 기록을 보존한다. 소유자에게는 `관리자 조치로 비공개`와 수정·문의 경로를 보여준다. 신고와 알림은 초기에 관리자 화면 내 기록과 사이트 내 알림으로 시작하고, 외부 자동 발송은 별도 결정한다.

**현재 코드에서 반드시 고칠 부분.** 브랜드 `disabled`는 공개 카탈로그에서 제외되지만, 뷰티 작업공간과 상품 API가 브랜드 상태를 다시 확인하지 않는 경로가 있다. 브랜드 이용 중단 시 작업공간 접근 및 쓰기 API도 함께 막아야 한다. 상품 `hidden`을 운영자 제재에 그대로 쓰면 소유자가 관리 화면에서 상품을 볼 수 없으므로, 소유자 숨김과 관리자 제재를 구분해야 한다. 제재 상품은 수정·재공개 권한을 서버에서 차단한다.

## 7. 첫 출시 범위

1. 뷰티 페이지 → 전용 가입 → 뷰티 센터 → 첫 상품 공개까지 연결한다.
2. 가입 입력을 최소화하고 기존 패션 신청 화면은 유지한다.
3. 상품 임시 저장·즉시 공개·미리보기와 상태 설명을 제공한다.
4. 관리자 상품 내리기·브랜드 중단·복구를 안전하게 만들고 조치 이유·이력을 남긴다.
5. 기존 공개 상품은 건드리지 않는다. 기존 브랜드 소유권 연결은 관리자 확인 절차로 처리한다.

후속 단계는 신고 접수 UI, 팀원 초대, 대량 상품 등록, 운영 리포트다. 결제·주문 연동·자동 정산은 이번 범위에 넣지 않는다.

## 8. 수용 기준

- 신규 브랜드가 사업자등록증·사업자번호·관리자 승인 없이 가입해 뷰티 센터에 들어간다.
- PC와 모바일에서 5분 안에 가입부터 첫 상품 공개까지 완료할 수 있는 흐름으로 설계·검증한다. 실제 평균 소요 시간은 출시 후 측정한다.
- 공개한 상품은 해당 브랜드의 뷰티 목록에 나타나고, 다른 브랜드 계정은 수정할 수 없다.
- 관리자가 상품을 내리면 공개 목록·상세·캠페인 선택에서 사라지고, 소유자가 직접 재공개할 수 없다.
- 관리자가 브랜드를 중단하면 모든 해당 상품이 공개 목록에서 빠지고 상품·캠페인 쓰기 요청이 서버에서 거부된다.
- 복구는 운영자만 할 수 있고, 이전 조치와 복구 이유가 남는다.
- 패션 디자이너의 기존 가입·스튜디오 흐름은 그대로 동작한다.
- 기존 뷰티 상품의 이미지·공개 상태는 이 변경으로 바뀌지 않는다.

## 9. 출시 확인과 지표

가입→첫 상품 공개의 실제 PC·모바일 흐름, 타 브랜드 접근 차단, 관리자 제재 후 재공개 차단, 브랜드 중단 후 API 쓰기 차단, 기존 패션 가입 회귀를 확인한다.

초기 4주에는 가입 시작 대비 완료율, 가입 후 첫 상품 공개율, 첫 상품 공개까지 걸린 시간, 관리자 조치 건수와 처리 시간, 복구 건수를 본다. 목표치는 실제 기준선이 생긴 뒤 정한다.

## 10. 남은 제품 결정

- 가입한 브랜드의 상품을 공개 카탈로그에 즉시 노출한다는 것은 사용자 요청을 반영한 기본안이다. 필요해지면 특정 고위험 카테고리만 예외 검토할 수 있다.
- 브랜드명 중복 발견 시 즉시 차단할지, 가입은 허용하고 운영자 확인 대상으로 보낼지 결정한다. 이 문서는 가입을 허용하고 확인 대상으로 보내는 안이다.
- 신고 접수 버튼을 첫 출시부터 공개 페이지에 둘지, 운영자 수동 발견·문의로 먼저 시작할지 결정한다. 이 문서는 관리자 처리 기능을 먼저 완성하는 안이다.
