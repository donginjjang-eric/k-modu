# 작업 맥락

- PC와 원격 저장소의 차이가 0개인 상태에서 시작했다.
- 캡처에서는 구글 로그인 뒤 센터 선택 화면에 진입했다. 뷰티·크리에이터 센터 선택 후에는 두 주소 모두 `https://0.0.0.0:8080`으로 이동했다.
- 기존 폼 성공 응답은 `new URL(redirectTo, request.url)`을 사용하며 내부 주소를 요청 주소로 주면 캡처의 두 이동 주소가 그대로 나온다. JSON으로 센터를 선택하는 가입 페이지는 이 분기를 사용하지 않는다.
- 선택 화면은 기존 로고, 아이보리 배경, 잉크색 텍스트와 세이지색 뷰티 카드에 맞춘다. PC는 두 열, 모바일은 한 열로 표시한다. 센터별 역할 설명과 이름이 구분되도록 하고 비어 있는 상태 목록은 생략한다.
- 기존 코드에서 새 회귀 테스트가 내부 주소를 실제로 반환해 실패했다. 수정 후 실제 라우트 함수에서 두 센터의 경로, 선택 쿠키, 뷰티 상품 경로, 가입 화면의 JSON 응답, 세션 만료 안내와 구글 계정 전환이 통과했다.
- 테스트 멤버십을 연결한 로컬 화면을 1440px과 390px로 렌더링했다. 크롬에서 두 선택 버튼을 각각 눌러 브라우저가 같은 호스트의 목적지로 이동하고 테스트 선택 쿠키를 유지하는 것을 확인했다.
- 집중 회귀 테스트 49개, 타입 검사와 webpack 운영 빌드가 통과했다. 별도로 실행한 대행사 인증 테스트의 구글 콜백 소스 검사 1건은 수정 전에도 없는 문자열을 기대했다. 해당 콜백 소스가 HEAD와 동일함을 확인했다.
