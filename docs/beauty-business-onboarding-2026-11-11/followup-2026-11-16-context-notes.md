# 작업 맥락

- 사용자가 전달한 카카오톡 캡처에는 뷰티 상품의 디자이너 화면 중복 노출, 등록한 상품 2개 중 1개만 보이는 현상, 노란 문의 버튼 색상 변경 요청이 있다.
- 캡처 속 디자이너 화면 상단 지표는 공개 `/designers`의 Registered Products·Designer Brands·AI Images Generated와 일치한다. 공개 디자이너 API는 현재 모든 승인 브랜드를 포함한다.
- 공개 뷰티 API에서 2026-11-16 현재 34개가 보인다. 최근 항목에는 마크브릿지의 물방울 썬크림, K-MODU MASTER BEAUTY의 여러 선크림, With Barda의 선크림 SPA 50+가 있다. 이것만으로 캡처 속 사용자의 두 상품을 특정할 수 없다.
- 현재 브라우저에는 K-MODU 로그인 세션이 없고 Railway CLI도 인증되지 않았다. 따라서 비공개 상품 상태·소유 계정은 아직 읽지 못했다. 운영 상품을 임의로 만들거나 이동하지 않는다.
- 뷰티 전용 브랜드는 공개 디자이너 목록과 상세·보드에서 제외한다. 복합 브랜드는 상품 카테고리로 패션과 뷰티 목록을 분리한다.
- 상품 관리 API도 선택한 작업공간과 카테고리를 함께 검사한다. 다른 분야 상품의 수정·삭제 요청은 404로 막는다.
- 로컬 운영 빌드는 `npx next build --webpack`으로 성공했다. 기본 Turbopack은 기존 `.next`의 sharp junction 생성 충돌(os error 80)로 실패했다. 코드 타입 오류는 아니었다.
- 로컬 PC 1440px·모바일 390px에서 파란 카카오 문의 버튼을 렌더링 확인했다. 로컬 운영 서버에는 DATABASE_URL이 없어 뷰티 상품 목록은 운영 데이터가 아닌 예시로 보였다.
- `463b970`을 origin/master에 올렸고 GitHub의 Railway 배포 상태가 success였다. 운영 디자이너 API는 20개에서 14개, 패션 상품 지표는 124개에서 90개로 바뀌었다. 운영 뷰티 상품 34개는 유지됐다.
- 운영 `/designers`, `/beauty`, `/beauty/join`은 200이다. 뷰티 전용 브랜드 With Barda의 디자이너 상세와 스타일링 보드는 404다. 운영 브라우저에서 문의 버튼 색상은 rgb(36, 88, 223), 모바일 390px에서는 가로 넘침이 없었다.
- 두 상품 중 하나가 사라졌다는 문의는 실제 로그인 계정의 상품명 2개 또는 인증된 상품 관리 자료 없이는 특정할 수 없다. 공개 API에는 최근 상품이 서로 다른 브랜드에 나뉘어 있으므로 관리 화면의 브랜드 식별·전환을 우선 고쳤다.
- 이후 제공된 확대 캡처로 색상 요청의 대상이 카카오 문의 버튼이 아닌 가입 화면의 기존 브랜드 센터 버튼임을 확인했다. 다음 수정에서 카카오 버튼 색상은 원복했다.
