# 뷰티 브랜드 셀프 가입·상품 공개 구현 계획

목표: 승인된 시안을 실제 뷰티 가입 화면으로 연결하고, 가입 직후 상품 등록·공개와 관리자 사후 조치가 안전하게 이어지게 한다.

구조: 뷰티 전용 가입 화면은 별도로 두되 기존 구글 로그인·users/designers/workspaces·뷰티 센터를 재사용한다. 상품은 기존 API로 등록하고 관리자 제재는 상품 승인 상태와 브랜드 상태를 서버에서 강제한다. 기존 패션 신청 흐름은 변경하지 않는다.

기술: Next.js 16, React 19, PostgreSQL, 기존 정적 뷰티 페이지와 서버 API.

근거: `docs/beauty-business-onboarding-2026-11-11/PRD.md`.

## 검증 범위

1. 뷰티 가입 입구와 구글 로그인 복귀. 비로그인·기존 가입·다중 브랜드·중복 신청을 확인한다.
2. 최소 정보 가입과 작업공간 선택. DB 트랜잭션·쿠키·권한 연결을 확인한다.
3. 대표 사진 업로드와 상품 즉시 공개. 공개 카탈로그·상세 진입을 확인한다.
4. 관리자 상품 제재·복구와 브랜드 중단·복구. 소유자 재공개·API 우회가 막히는지 확인한다.
5. 기존 패션 가입·상품·관리자 화면의 회귀 테스트와 PC·모바일 화면 검수.
6. 운영 배포 후 라이브 경로 확인과 쉬운 브리핑 문서.

## 파일 경계

- `beauty.html`, 뷰티 가입 페이지/스타일: 공개 입구와 가입 UI.
- `src/app/api/beauty/signup/route.ts`, `src/lib/beauty-signup.ts`: 가입 입력 검증과 계정·작업공간 연결.
- `src/lib/auth.ts`: 비활성 브랜드의 센터/API 차단.
- `src/app/api/products/*`, `src/lib/db.ts`: 제재 상품의 소유자 재공개 차단.
- `src/app/api/admin/products/[id]/route.ts`, `src/components/AdminProductsManager.tsx`: 상품 제재·복구.
- `src/app/api/admin/designers/[id]/disable/route.ts`, 관리자 브랜드 동작: 브랜드 중단·복구.
- `db/schema.sql`: 필요한 최소 운영 이력·상태 저장.
- `tests/*`: 신규 가입·권한·공개/제재 계약 및 기존 회귀.

## 작업과 확인

- [x] 가입 화면과 뷰티 페이지 CTA를 연결한다. PC/모바일 렌더와 로그인 복귀 URL을 확인했다.
- [x] 가입 API의 검증·중복 방지·작업공간 쿠키를 구현한다. 주입형 트랜잭션 테스트를 통과했다.
- [x] 첫 상품 등록·공개 흐름을 연결한다. 기존 이미지 업로드·공개 카탈로그 계약 테스트를 통과했다. 실제 계정 등록은 미검증이다.
- [x] 관리자 사후 조치를 서버 권한과 묶는다. 제재 뒤 소유자 API 차단과 공개 제외를 코드·계약 테스트로 확인했다.
- [x] 관련 테스트 66개와 전체 빌드, 실제 브라우저 경로 검수 후 배포했다.
- [x] 운영 확인 결과와 남은 제약을 브리핑 문서에 기록했다.
